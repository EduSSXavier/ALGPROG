Encapsulamento

O que é Encapsulamento?

O encapsulamento é um princípio da programação orientada a objetos que consiste em agrupar os dados (atributos) e os métodos (funções) que operam sobre esses dados em uma única unidade, chamada de classe. Ele também permite controlar o acesso aos atributos e métodos de uma classe, protegendo-os de modificações externas não autorizadas.


Por que encapsular?

  • Segurança: Proteger os dados internos da classe, evitando que eles sejam acessados diretamente ou modificados de fora dela
  • Manutenibilidade: Permitir que as classes sejam modificadas sem afetar outras partes do código
  • Controle de acesso: Define quem pode ler ou modificar os dados
  • Validação: Permite verificar dados antes de armazená-los e evitar erros
  • Flexibilidade: Permite a adição de novos comportamentos sem afetar o código existente

Níveis de Visibilidade em Python

Em Python, a visibilidade é indicada através de underscores:

  • Público: atributo - pode ser acessado de qualquer lugar
  • Privado: _atributo - indica visibilidade interna ou uso interno (convenção, não bloqueio real)
  • Protegido: __atributo - dificulta o acesso externo através de name mangling (ou mutilação/confusão de nomes)

Exemplos

class Pessoa:
    def __init__(self, nome, email, fone):
        self.nome = nome # Atributo público
        self._email = email # Atributo privado
        self.__fone = fone # Atributo protegido
    def apresentar(self):
        print("==============================")
        print(f"Olá, meu nome é {self.nome}")
        print(f"Meu email é {self._email}")
        print(f"Meu telefone é {self.__fone}")
        print("==============================")

alguem = Pessoa("Maria", "maria@gmail.com", "9999-9999")
print(alguem.nome)      # Isto funciona
print(alguem._email)    # Isto também funciona, mas não deve ser usado
print(alguem.__fone)    # Isto não funciona (erro)

alguem.apresentar()

Métodos de Encapsulamento

1. Criando Getters e Setters Manualmente

Podemos criar métodos "getter" e "setter" tradicionais de form manual. Essa é uma abordagem mais explícita e comum em outras linguagens como Java, podendo ser facilmente implementada em Python.


Exemplos

class Produto:
    def __init__(self, nome, preco):
        self.__nome = nome # Atributo privado
        self.__preco = preco
    
    # Getter para nome
    def get_nome(self):
        return self.__nome
    
    # Setter para nome
    def set_nome(self, nome):
        if not nome or len(nome) < 3:
            raise ValueError("Nome deve ter pelo menos 3 caracteres")
        self.__nome = nome

    # Getter para preço
    def get_preco(self):
        return self.__preco

    # Setter para preço
    def set_preco(self, preco):
        if preco < 0:
            raise ValueError("Preço não pode ser negativo")
        self.__preco = preco

    # Outros métodos da classe
    def aplicar_desconto(self, percentual):
        """Aplica desconto ao produto"""
        if percentual < 0 or percentual > 100:
            raise ValueError("Desconto deve estar entre 0 e 100%")
        desconto = self.__preco * (percentual / 100)
        self.__preco -= desconto
        print(f"Desconto de {percentual}% aplicado!")

# ----- Como usar -----

# Criando produto
produto = Produto("Notebook", 3000)

# Usando getters
print(f"Produto: {produto.get_nome()}")
print(f"Preço: R$ {produto.get_preco():.2f}")

# Usando setters
produto.set_nome("Notebook Gamer")
produto.set_preco(3500)

# Aplicando desconto
produto.aplicar_desconto(10)
print(f"Novo preço: R$ {produto.get_preco():.2f}")

2. Usando Decorators

Como funciona?

O decorador @property é a forma mais "pythônica" de implementar encapsulamento. Ele permite criar métodos que se comportam como atributos.

Por que usar?

Quando queremos criar uma propriedade (atributo) que se comporta como um metodo, o decorator @property é uma opção.

Mas o que é um decorator?

Um decorator é uma função que recebe outra função como argumento e retorna uma nova função com comportamento modificado. Ele é usado para adicionar funcionalidades a funções ou métodos existentes sem alterar seu código-fonte original.

Em Python, os decorators são frequentemente usados para:

  • Adicionar funcionalidades a métodos de classes
  • Implementar padrões de projeto, como Singleton ou Observer
  • Controlar acesso a métodos (autenticação, autorização)
  • Medir tempo de execução de funções

Aplicando um decorator @property em POO

O decorator @property (que já existe previamente) permite que criemos um getter e um setter para um atributo privado. Ele transforma métodos em propriedades, permitindo que sejam acessados como atributos, mas com a lógica de validação ou processamento encapsulada.

Exemplo @property:

class Produto:
    def __init__(self, nome, preco):
        self.__nome = nome # Atributo privado
        self.__preco = preco
    
    @property
    def nome(self):
        """Getter para o nome"""
        return self.__nome
        # Setter para nome

    @nome.setter
    def nome(self, nome):
        """Setter para o nome com validação"""
        if not nome or len(nome) < 3:
            raise ValueError("Nome deve ter pelo menos 3 caracteres")
        self.__nome = nome
    
    @property
    def preco(self):
        """Getter para o preço"""
        return self.__preco
    
    @preco.setter
    def set_preco(self, preco):
        """Setter para o preço com validação"""
        if preco < 0:
            raise ValueError("Preço não pode ser negativo")
        self.__preco = preco

# ----- Como usar -----

# Criando objeto
prod = Produto("Caneta", 10.0)

# Acessando como se fossem atributos normais (usando o getter)
print(prod.nome)    # Caneta
print(prod.preco)   # 10.0

# Modificando com validação automática (usando o setter)
prod.nome = "Borracha"
prod.preco = 3.5

# Tentativa de atribuir valor inválido (gera erro)
prod.preco = -5 # Vai gerar erro!

Diferença entre @property e get/set

@property get/set
Mais "pythônico" Mais explícito, comum em outras linguagens
Permite acessar métodos como atributos (obj.nome) Requer chamadas explícitas de métodos (obj.get_nome())
Validação e lógica encapsuladas Validação e lógica podem ser separadas
Recomendado em Python Usado em Java, C++,... (também funciona em Python)

Associação

O Conceito de Associação entre Objetos

Associação representa relacionamentos entre objetos de diferentes classes. É quando um objeto "conhece" ou "usa" outro objeto.

Tipos de associação

Agregação:

  • Relação "tem um" (has-a) fraca
  • Um objeto pode existir sem o outro
  • Exemplo: Carro tem Motor

Composição:

  • Relação "tem um" (has-a) forte
  • Um objeto não existe sem o outro
  • Exemplo: Casa tem Cômodos

Associação simples:

  • Objetos se relacionam mas não há "propriedade"
  • Exemplo: Professor leciona Disciplinas



Exemplo de Associação:

class Endereco:
    def __init__(self, rua, numero, cidade):
        self.rua = rua
        self.numero = numero
        self.cidade = cidade
    def __str__(self):
        return f"{self.rua}, {self.numero} - {self.cidade}"

class Pessoa:
    def __init__(self, nome, endereco):
        self.nome = nome
        self.endereco = endereco # Associação: Pessoa tem um Endereço
    def exibir_info(self):
        print(f"Nome: {self.nome}")
        print(f"Endereço: {self.endereco}")

# Criando objetos associados
endereco = Endereco("Av. Paulista", 1000, "São Paulo")
pessoa = Pessoa("João", endereco)
pessoa.exibir_info()

Cardinalidade:

  • 1:1 (um para um): Uma pessoa tem um CPF
  • 1:N (um para muitos): Um autor escreve vários livros
  • N:N (muitos para muitos): Alunos cursam várias disciplinas, disciplinas têm vários alunos

Exercício 3

Crie classes Autor e Livro com associação 1:N (um autor pode ter vários livros). Implemente métodos para adicionar livros ao autor e listar todos os livros.

Tente aplicar os seguintes conceitos:

  • Associação 1:N (Um autor possui múltiplos livros)
  • Encapsulamento (Atributos protegidos com @property)
  • Validação de dados (Verifica se o objeto adicionado é realmente um Livro)
  • Lista interna (A coleção de livros é gerenciada internamente, sem manipulação externa direta)
class Livro:
    def __init__(self, titulo: str, ano: int):
        self.__titulo = titulo
        self.__ano = ano

    @property
    def titulo(self):
        return self.__titulo

    @property
    def ano(self):
        return self.__ano

    def __str__(self):
        return f"'{self.__titulo}' ({self.__ano})"

class Autor:
    def __init__(self, nome: str):
        self.__nome = nome
        self.__livros = []  # Lista interna - não deve ser manipulada diretamente

    @property
    def nome(self):
        return self.__nome

    @property
    def livros(self):
        """Retorna uma cópia da lista para evitar manipulação externa direta."""
        return self.__livros.copy()

    def adicionar_livro(self, umLivro):
        """Adiciona um livro ao autor com validação."""
        if not isinstance(umLivro, Livro):
            raise TypeError("Só é possível adicionar objetos da classe Livro.")
        
        if umLivro in self.__livros:
            raise ValueError(f"O livro {umLivro} já está associado a este autor.")
        
        self.__livros.append(umLivro)

    def listar_livros(self):
        """Lista todos os livros do autor."""
        if not self.__livros:
            print(f"O autor {self.__nome} ainda não possui livros cadastrados.")
            return

        print(f"Livros de {self.__nome}:")
        for umLivro in self.__livros, 1:
            print(f"Título: {umLivro.titulo} - Ano: {umLivro.ano}")


# --- Exemplo de uso ---
autor = Autor("Machado de Assis")

livro1 = Livro("Dom Casmurro", 1899)
livro2 = Livro("Memórias Póstumas de Brás Cubas", 1881)
livro3 = Livro("Quincas Borba", 1891)

autor.adicionar_livro(livro1)
autor.adicionar_livro(livro2)
autor.adicionar_livro(livro3)

autor.listar_livros()

Projeto Prático

Gerenciamento de Escola

Vamos criar um sistema completo que demonstra encapsulamento e associação entre três classes: Aluno, Turma e Disciplina. O sistema permitirá consultar dados e visualizar os relacionamentos

Relacionamentos:

  • Uma Disciplina pode ter várias Turmas
  • Uma Turma pertence a uma Disciplina e tem vários Alunos
  • Um Aluno pode estar matriculado em várias Turmas

Sugestão:

Além das classes Aluno, Turma e Disciplina, crie uma classe SistemaEscolar que areha todas essas classes, além de todos os métodos necessários para o funcionamento do sistema (exemplo: consultar dados de um aluno, matricular um aluno, etc).

Para ganhar tempo, não nos preocuparemos em criar interfaces gráficas para interagir com o sistema. Basta implementar as classes e seus métodos.
